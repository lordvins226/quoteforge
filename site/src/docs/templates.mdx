A template defines the layout — the spatial grammar of a card. QuoteForge ships **28
templates**, grouped into five families, all built on a shared responsive base. Pick one per
card via the `template` field, or from the grouped picker in the studio's toolbar.

Every block type uses one of three shapes: `parts: Part[]` (`headline`, `blockquote`),
`content: string` (`text`), or `items: LabeledItem[]` (`bullet-list`, `callout`) — plus three
type-specific shapes for `stat`, `code`, and `chart`. See [Content Schema](/docs/content-schema)
for the full block reference. Many templates below **reinterpret** what a `LabeledItem`'s
`label` and `text` mean — that's the single most useful thing to know before writing content
for a given template, and it's called out per template.

## Statement

Single-idea, declaration-style cards. Headline- and blockquote-led.

### `manifesto`
Left-aligned, authoritative top-down flow with tightened headline letter-spacing. Best for
bold declarations and thesis statements.

- **Blocks:** all types (`headline`, `blockquote`, `text`, `bullet-list`, `callout`, `divider`,
  `spacer`, `image`, `stat`, `code`, `chart`).
- **`label`:** default `LabeledItem` meaning — the bullet/callout marker text.
- **Sizes:** demoed at `instagram-sq` (1080×1080, 1:1).

## Structure & data

Rows, grids, and figures — for content that's naturally tabular or sequential.

### `list`
Numbered or bulleted rhythm with even vertical distribution and tighter, data-dense spacing.
Best for "5 lessons", "10 tips" decks.

- **Blocks:** all types.
- **`label`:** default meaning.
- **Sizes:** demoed at `instagram-port` (1080×1350, 4:5).

![list](/samples/templates/list.png)

### `ledger`
Ruled key/value rows under a heavy header rule, with hairlines separating rows.

- **Blocks:** `headline` (header), `bullet-list`/`callout` (rows), `text` (trailing block
  becomes a muted mono footer).
- **`label`:** the row's key (left column); `text` is the value.
- **Sizes:** demoed at `instagram-port` (1080×1350, 4:5).

![ledger](/samples/templates/ledger.png)

### `index`
Table-of-contents rows connected by dot leaders.

- **Blocks:** `headline` (title), `bullet-list`/`callout` (rows).
- **`label`:** the figure at the right edge (a page number, a count); `text` is the entry it
  points at.
- **Sizes:** demoed at `instagram-sq` (1080×1080, 1:1).

![index](/samples/templates/index.png)

### `grid`
A 2×2 grid of exactly 4 cells, drawn from `bullet-list`/`callout` items.

- **Blocks:** `bullet-list`/`callout` only.
- **`label`:** the cell's accent chip; `text` is the cell's body.
- **Constraint:** requires exactly 4 items across the qualifying blocks. Any other count still
  renders, but unevenly — the CLI now warns (`templateWarnings` in
  `src/renderer/template-warnings.ts`), it does not fail.
- **Sizes:** demoed at `instagram-sq` (1080×1080, 1:1).

![grid](/samples/templates/grid.png)

### `timeline`
A vertical spine with dated nodes.

- **Blocks:** `headline` or a first `text` block (title), `bullet-list`/`callout` (nodes).
- **`label`:** the time marker (e.g. "Shipped", "Q3", a date); a trailing `*` marks the node
  complete — completed nodes fill with the accent color, pending nodes stay outlined. `text`
  is the event description.
- **Sizes:** demoed at `instagram-port` (1080×1350, 4:5).

![timeline](/samples/templates/timeline.png)

### `versus`
A symmetric two-column comparison split by a center rule.

- **Blocks:** `bullet-list`/`callout` only — the first qualifying block's first two items
  supply both sides; extra items are ignored, and a single item drops the divider for one
  centered column.
- **`label`:** the side's caption (e.g. "Before"/"After"); `text` is the large value shown.
- **Sizes:** demoed at `twitter` (1200×675, 16:9).

![versus](/samples/templates/versus.png)

### `stat`
One oversized figure with an optional unit and note — built around the `stat` block type.

- **Blocks:** all types, including `stat` (its primary content).
- **`label`:** n/a for `stat` blocks — see `label`/`value`/`unit`/`note` on the block itself in
  [Content Schema](/docs/content-schema). Default `LabeledItem` meaning for any `bullet-list`/
  `callout` blocks also present.
- **Sizes:** demoed at `instagram-sq` (1080×1080, 1:1).

![stat](/samples/templates/stat.png)

### `chart`
Horizontal bars rendered with pure CSS — no chart library — built around the `chart` block
type.

- **Blocks:** all types, including `chart` (its primary content). An optional `headline`
  supplies the title, a trailing `text` block becomes the footer.
- **`label`:** on each `chart` row, `label` is the bar's caption and `value` (0–100) sets the
  fill width; `unit` (default `%`) is appended after the number.
- **Sizes:** demoed at `instagram-port` (1080×1350, 4:5).

![chart](/samples/templates/chart.png)

## How templates work

Each template lives under `templates/<name>/`:

```
templates/
└── manifesto/
    ├── template.njk    # Nunjucks layout
    └── style.css       # Template-specific styles (uses theme vars)
```

All templates **inherit a shared base CSS** (`templates/_base.css`) that handles:

- Flex-based top-to-bottom block distribution
- Dimension-aware font scaling
- Puppeteer-ready font loading gates
- Callout, divider, spacer, quote, and image rendering (image width + alignment)

Template CSS only adds personality on top — letter-spacing, border weights, radius tweaks.

## Responsive scaling

The renderer injects three computed variables at render time based on card dimensions:

```ts
areaScale = sqrt(w * h) / 1080
aspectPenalty = max(0.6, aspectRatio^0.65)
typeScale = min(areaScale * aspectPenalty * 1.5, 1.25)
```

So a 1080×1080 Instagram card and a 1080×1920 Story render with proportionally tuned type — the
same JSON looks right at every size.

## Adding a custom template

Create a folder under `templates/` with a `template.njk` and `style.css`:

```njk
{# templates/editorial/template.njk #}
<article class="card template-editorial">
  {% for block in blocks %}
    {% include "_blocks/" + block.type + ".njk" %}
  {% endfor %}
</article>
```

```css
/* templates/editorial/style.css */
.template-editorial .headline {
  font-family: var(--font-heading);
  text-transform: uppercase;
  letter-spacing: 0.04em;
}
```

Reference by name in your card JSON:

```json
{ "template": "editorial", ... }
```

In a repo checkout this works immediately — templates are auto-discovered by reading the
`templates/` directory at startup, and an unknown name now fails fast with a clear error
(`Unknown template "<name>". Available: ...`) instead of a silent blank render.

**A released binary is different.** Binaries embed template and theme assets at build time
(`src/assetBundle.ts`), so a folder that only exists in the repo won't be picked up by an
installed binary. Shipping a new template in a release requires registering both its files in
`TEMPLATE_ASSETS`:

```ts
import editorial_template from "../templates/editorial/template.njk" with { type: "text" };
import editorial_style from "../templates/editorial/style.css" with { type: "text" };
// …
const TEMPLATE_ASSETS: AssetMap = {
  // …
  "editorial/template.njk": editorial_template,
  "editorial/style.css": editorial_style,
};
```

Auto-discovery, in other words, is only half true — true for a repo checkout, false for a
built binary until the template is registered there too.

## Constraints

- **Never hardcode colors** in template CSS. Use `var(--color-*)` exclusively.
- **Never set fixed pixel font sizes** without `calc(var * --type-scale)` — cards render at
  multiple dimensions.
- **Always flex-distribute blocks vertically** so content fills the card top-to-bottom instead
  of bunching mid-card.
- **`eyebrow` only renders on 8 of the 28 templates** — `cover`, `memo`, `receipt`, `split`,
  `spotlight`, `terminal`, `ticket`, `window`. Setting it on any other template validates (it's
  a plain optional string on the schema) but renders nothing; the CLI now warns when this
  happens rather than failing silently.
- **`grid` requires exactly 4 items.** Any other count still renders — the CLI warns instead of
  blocking — but the layout comes out uneven.
- **15 of the 28 templates render only a subset of block types** and drop the rest. A
  `headline` on `memo`, a `text` block on `ticket`, anything but `bullet-list`/`callout` on
  `grid`, `versus`, and `prompt` — the card validates, renders, and exits 0 with your content
  missing from the image. The **Blocks** line on each template above is authoritative. Since
  1.2.0 the CLI warns when a card carries a block its template will drop; treat that warning
  as an error, because it means content you wrote is not in the output.

The shared `_base.css` already handles color/font-scale/flex-distribution correctly; only add
overrides when truly needed.
